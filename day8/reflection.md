# Day 8 Reflection

The most difficult concept in this course was understanding how databases handle simultaneous requests, especially when many users try to book the same seat at the same time. At first, I thought that using a cache or a waiting room would be enough to prevent double-booking. I learned that the real protection comes from database transactions, atomic conditional updates, and unique constraints. I overcame this challenge by reviewing examples, answering practice questions, and applying the concepts to the TicketHub design.

For my capstone project, I would improve the monitoring and testing of the system. Based on the feedback I received on my design work, I understand that database performance and indexing are important when applications grow. I would add more detailed performance tests, improve database indexing, and test how the system behaves when many users access it simultaneously. This would help make the capstone more reliable and ready for real-world use.

Next, I want to learn more about backend development, database optimization, cloud infrastructure, and deploying scalable applications. I also want to practise building real APIs and connecting them to databases. These skills will help me move from designing systems to building and maintaining them.
